# Testing two Community Hubs on one public IP (2.3.14)

Use different public host ports and different persistent data volumes. The WebSocket P2P transport shares each Hub's HTTP gateway port; no separate libp2p public listener is opened.

Example when Hub A uses `8182` and Hub B uses `8181`:

| Setting | Hub A | Hub B |
|---|---|---|
| `HOST_PORT` | `8182` | `8181` |
| `HUB_PUBLIC_URL` | `http://14.176.78.46:8182` | `http://14.176.78.46:8181` |
| `P2P_FIXED_SEEDS` | `http://14.176.78.46:8181` | `http://14.176.78.46:8181` |
| Docker mapping | `8182:8080` | `8181:8080` |
| Data volume | unique to A | unique to B |

Recommended P2P settings (defaults):

```env
P2P_ENABLED=true
P2P_WS_GATEWAY=true
P2P_PEER_CRAWL=true
P2P_CRAWL_PER_CYCLE=4
P2P_MIN_PEERS=3
```

Important:

1. Keep the two Hub data volumes separate; otherwise identities and peer records can collide.
2. Forward TCP 8181 and TCP 8182 to the same Docker host, each to its corresponding container port 8080.
3. Check `/p2p/bootstrap` on both public URLs. Each response should have its own `peer_id` and a multiaddr whose port matches that Hub's public URL.
4. The Hub on 8182 should appear in the Hub on 8181's `/p2p/bootstrap` peer list after registration.
5. If the router does not support NAT loopback, the two containers may not be able to dial one another via the public IP from inside the same LAN. Use a third device outside the LAN to verify the real public dial.
6. `0 links` means no authenticated libp2p connection has been established; “ready to connect” only means the local P2P service is prepared.

One public IP with two ports is not high availability. For resilient bootstrap, add multiple `P2P_FIXED_SEEDS` on separate public hosts.
